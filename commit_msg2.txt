Fix three account/settings gaps: display name next to pfps, pfp vanishing on refresh, missing Blossom server UI

- App.tsx: the account button showed only the avatar pfp, never the
  logged-in user's display name next to it, even when one had been
  fetched. Added an account-btn-name span (only shown once logged in
  and a profile name exists), with matching CSS to grow the pill-shaped
  button width instead of staying a fixed circle.

- useProfile.ts: root-caused the "pfp disappears on refresh, only
  comes back after logging out/in" bug. getSharedRelayPool() can be
  null on first mount (the pool exists but no relay has finished
  connecting yet), and the old code did a single null-check and bailed
  for good if it wasn't ready that instant -- the profile fetch simply
  never happened that session unless something else (like a login
  state change) re-ran the effect later, after the pool happened to be
  up. Replaced the single check with waitForSharedPool(), which polls
  every 250ms for up to 8s before giving up, so the fetch actually
  waits for the pool instead of silently skipping it.

- settingsStore.ts + SettingsPanel.tsx: settings.blossom.servers has
  existed in the type/defaults since the initial scaffold but never
  had any UI or store actions (addBlossomServer/removeBlossomServer)
  to manage it -- the Relays tab only showed Nostr relays, with no
  way to see or edit which Blossom servers .torrent files get fetched
  from. Added a Blossom servers list/add/remove section under the
  Relays tab, plus a defensive blossom.servers migration entry
  matching the existing relays one.
